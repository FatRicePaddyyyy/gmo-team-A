# UX デザイン ベストプラクティス

## 1. 基本原則

### ユーザー中心設計
- 仮定ではなく **観察・テスト** に基づいて決める
- 「ユーザーがわからなかったらユーザーのせい」ではなく「設計のせい」
- 「自分が使える」≠「誰でも使える」

### 認知負荷を下げる
- 1 画面 1 目的。1 アクション 1 クリック
- 既存のメンタルモデルを活用（カートアイコン＝購入、赤＝エラー、緑＝成功）
- ナビゲーションは慣習に従う（主要ナビは上部、ユーティリティは右上）

---

## 2. 視覚的階層（Visual Hierarchy）

**ブラーテスト**: デザインを 10% に縮小しても主要アクションが見えるか確認する。

```
重要度の表現方法:
  大きさ   → 重要なものほど大きく
  コントラスト → 行動を促すボタンは高コントラスト
  位置     → 左上から右下へ視線が流れる（F字・Z字パターン）
  空白     → 余白が多い要素は重要に見える
```

**ドメインサービスへの応用:**
- 検索フォームが最大の要素 → 一番目立つ場所に
- 「カートへ追加」ボタンは赤（ブランドカラー）で大きく
- 価格は太字・大きく、更新価格は小さく補足として表示

---

## 3. フィードバック設計

ユーザーの操作には **100ms 以内** に反応を返す。

| 操作 | フィードバック |
|------|--------------|
| ボタンクリック | 押下状態 → ローディング → 成功/失敗 |
| フォーム入力 | リアルタイムバリデーション（blur 時） |
| 1秒以上かかる処理 | プログレスインジケーター |
| 非同期完了 | トースト通知またはステータス更新 |

```tsx
// ✅ ローディング中はボタンを disabled + テキスト変更
<Button disabled={isLoading}>
  {isLoading ? "処理中..." : "ドメインを登録する"}
</Button>
```

## 4. エラー設計

### エラーメッセージの原則

| ❌ 悪い例 | ✅ 良い例 | 理由 |
|----------|----------|------|
| 「エラーが発生しました」| 「ドメイン名に使用できない文字が含まれています」| 何が問題か明示 |
| 「Invalid input」| 「メールアドレスの形式が正しくありません（例: user@example.com）」| 修正方法を示す |
| 「Something went wrong」| 「ドメインの登録に失敗しました。時間をおいて再試行してください」| 次のアクションを示す |
| 「Error 409」| 「このドメインはすでに登録済みです。別のドメイン名をお試しください」| ユーザー言語で伝える |

### エラーメッセージの構造
```
[何が問題か] + [なぜそうなったか（任意）] + [どうすればよいか]

例: 「カード番号が不完全です。16桁すべてを入力してください」
     ↑ 何が問題      ↑ なぜ               ↑ 次のアクション
```

### エラー表示の位置
- フォームエラー → 該当フィールドの **直下**（上部まとめ表示は補助）
- ページエラー → コンテンツの **上部**
- 成功メッセージ → トースト通知（3秒自動消滅）

## 5. フォーム設計

### 入力フィールドの原則

```
✅ ラベルは常に表示（placeholder だけに頼らない）
✅ 必須項目は「*」マーク + ページ上部に「* は必須項目です」
✅ フィールドは縦 1 列（モバイルで横並びにしない）
✅ 関連フィールドはグループ化して視覚的に区切る
✅ 自動補完属性を設定（autocomplete="email" 等）
```

```html
<!-- ✅ 良い例 -->
<label for="email">メールアドレス <span aria-hidden="true">*</span></label>
<input id="email" type="email" autocomplete="email" required
       placeholder="user@example.com" aria-required="true">
<p role="alert" class="error">メールアドレスを入力してください</p>

<!-- ❌ 悪い例: ラベルなし、placeholder のみ -->
<input type="email" placeholder="メールアドレス">
```

### ボタンラベル設計

| ❌ 曖昧 | ✅ 具体的 |
|---------|---------|
| 「次へ」| 「支払いに進む」|
| 「送信」| 「申し込みを確定する」|
| 「OK」 | 「ドメインを削除する」|
| 「はい」| 「カートに追加する」|

**ルール**: ボタンを読んだだけで何が起きるかわかること。

## 6. プログレッシブ・ディスクロージャー（段階的開示）

複雑な操作は段階に分けて提示する。一度に全部見せない。

```
ドメイン登録フローの例:
  Step 1: ドメイン検索         ← 最小の入力
  Step 2: TLD・年数選択         ← 選択肢を提示
  Step 3: オプション追加        ← 任意の追加
  Step 4: 会員情報・確認        ← まとめて確認
  Step 5: 支払い               ← 最後に決済
```

各ステップでは「今どこにいるか（ステッパー）」を常に表示する。

---

## 7. 空の状態（Empty State）設計

リストや検索結果が空のとき、ユーザーを迷わせない。

```
構成:
  1. アイコン（状況を視覚的に示す）
  2. 見出し（何もない理由）
  3. 説明文（次にすること）
  4. アクションボタン（すぐ動ける）

例（ドメイン一覧が空の場合）:
  🌐 まだドメインがありません
  取得したいドメイン名を検索して、最初のドメインを登録しましょう。
  [ドメインを検索する]
```

## 8. モバイルファースト設計

- タッチターゲット最小 **44×44px**（Apple HIG 基準）
- テキストリンクより **ボタン** を使う（タップ領域が広い）
- 重要なアクションは **親指が届く範囲**（画面下部）に配置
- フォームはモバイルキーボードの種類を指定（`inputmode="numeric"` 等）

---

## 9. アクセシビリティ（A11y）最低基準

| 項目 | 基準 |
|------|------|
| コントラスト比 | 本文 4.5:1 以上、大見出し 3:1 以上 |
| キーボード操作 | Tab で全要素にアクセスできる |
| スクリーンリーダー | `alt` テキスト、`aria-label`、セマンティック HTML |
| フォーカスリング | 視覚的に明確に表示（`outline: none` を安易に使わない） |
| エラー関連付け | `aria-describedby` でエラーをフィールドに紐付け |

## 10. ドメインサービス特有のUX指針

### 検索体験
- 入力中にリアルタイムでサジェスト（TLD の候補）
- 空き確認中は「検索中...」を表示
- 結果は「取得可能」を上に、「取得済み」を下に分けて表示
- 「.com が空いています」という肯定的な表現を使う

### 価格表示
- 初年度価格と更新価格を必ず両方表示（1年目だけ安い商品の罠を避ける）
- 「0円（2年目以降 1,408円/年）」と明示

### エラーシナリオ
| シナリオ | メッセージ |
|---------|----------|
| ドメイン取得済み | 「このドメインはすでに登録されています。別の名前や TLD をお試しください」|
| 無効な文字 | 「ドメイン名に使用できるのは英数字とハイフンのみです」|
| TLD 非対応 | 「この TLD には対応していません。.com / .net / .jp などをお試しください」|
| タイムラグ競合 | 「申し訳ありません。検索から時間が経ち、このドメインは取得済みになりました。再度検索してください」|
| 決済エラー | 「カードの決済に失敗しました。カード情報を確認するか、別のお支払い方法をお試しください」|

### 信頼性の表現
- 「国内シェア No.1」「24時間365日サポート」などの数字・実績を載せる
- SSL バッジ、セキュリティマークを表示
- 価格は消費税込みで明示

## 11. チェックリスト

**画面設計時の確認:**
- [ ] 1 画面に主要アクションが 1 つに絞られている
- [ ] エラーメッセージに「何が問題か」「どうすれば良いか」が書かれている
- [ ] フォームラベルがプレースホルダーだけに頼っていない
- [ ] ボタンテキストが「次へ」「送信」のような曖昧な言葉でない
- [ ] ローディング中の表示がある
- [ ] 空の状態（検索結果 0 件など）のデザインがある
- [ ] タッチターゲットが 44px 以上ある
- [ ] コントラスト比が 4.5:1 以上ある
- [ ] ステッパーなど「今どこにいるか」が分かる
