## お名前.comの実際のフロー（調査結果）

### 1. ドメイン登録（check → create）

**7ステップ構成**:
1. 文字列を検索窓に入力
2. 取得可能なドメインを選択（TLD選択含む）
3. 用途選択（ブログ・ホームページ等）
4. オプション（サーバー等）選択
5. ログイン or 新規会員登録（メアド＋PW入力）
6. 会員情報・支払い方法入力
7. 申込み完了

→ **簡易版では**: 検索 → 選択 → ログイン/登録 → 確認・支払い → 完了（5ステップ程度に簡略化可）

---

### 2. ドメイン更新（renew）

**フロー**:
1. Navi（管理画面）にログイン
2. 「ドメイン契約更新」ページへ（`navi.onamae.com/domain/setting/renew/list`）
3. 更新したいドメインを選択
4. 支払い方法確認
5. 「次へ」→「申し込む」で完了

→ **ダッシュボードとは独立した「更新リスト」画面が存在する**

---

### 3. 情報修正（update）

**ドメイン詳細画面から可能な操作**:
- ネームサーバー変更（/guide/p/67）
- Whois情報変更（コンタクト情報）
- 自動更新設定変更
- Whois情報公開代行設定

→ **詳細画面がハブになっており、そこから各編集画面へ遷移**

---

### 4. ドメイン廃止（delete）

**お名前.comでの実際の廃止方法**:
- 明示的な「削除ボタン」は存在しない
- **自動更新設定をOFFにする** → 有効期限が来ると自動廃止
- 有効期限の16日前までに自動更新をOFFにする必要あり

→ **本ハッカソンアプリでは `DELETE /api/v1/epp/domains/{name}` を直接呼ぶ「廃止ボタン」UIとして実装する（EPP準拠）**

---

### 5. ドメイン復旧（restore / RGP）

**フロー**:
1. Naviにログイン
2. 「廃止済みドメイン復旧」ページへ
3. 復旧したいドメインを選択
4. 更新料金＋復旧手数料を支払い
5. 申請完了（2〜5営業日程度で復旧）

**重要事項**:
- 復旧可能期間はドメイン種別により異なる
- 追加費用（復旧手数料）が発生
- 銀行振込の場合は入金確認後に処理開始

→ **UIでは「Grace Period中のみ」復旧ボタンを表示。費用発生の警告も必要**

---

### 6. ドメイン移管IN（transfer request）

**フロー**:
1. 移管するドメイン名を入力（複数可）
2. 「移管可否を確認する」ボタン → 移管可否チェック
3. AuthCode（移管パスフレーズ）を入力
4. ログイン or 新規会員登録
5. 支払い
6. 申請完了（10日前後かかる）
7. 現レジストラ（losing）が承認 or 自動承認

→ **「移管可否確認」が authCode入力より先**  
→ **Naviからの申請（ログイン済み）と TOPページからの申請（未ログイン）の2ルート**

---

### 7. ドメイン詳細（info）

**確認できる情報**:
- ドメイン名 / 登録日 / 有効期限 / 更新期限
- 自動更新設定状況
- ステータス（状態）
- Whois情報公開代行設定状況
- AuthCode
- ネームサーバー情報
- 変更履歴

**この画面から可能な操作**:
- ドメイン契約更新
- 自動更新設定変更
- Whois情報公開代行設定変更
- ネームサーバー変更
- Whois情報変更

## Navi（管理画面）のメニュー構造

```
お名前.com Navi
├── ドメインの更新
│   ├── ドメイン自動更新の設定/解除
│   ├── 廃止済みドメイン復旧（restore）
│   └── ドメイン契約更新（renew）
├── ドメインの登録
│   └── ドメインの登録（check → create）
├── ドメインの移管
│   ├── お名前.comへの移管申請（transfer IN）
│   ├── 移管状況確認/AuthCode修正
│   └── ドメイン移管ロック
├── ドメイン情報の設定
│   ├── コンタクト情報設定（update）
│   ├── ドメインWhois情報変更（update）
│   └── Whois情報公開代行
├── ドメイン廃止（解約）
│   └── 自動更新OFFで期限切れ廃止（delete）
└── ドメイン一覧
    ├── ドメイン詳細情報確認（info）
    └── 管理ドメイン確認
```

## 前回の遷移図との差異まとめ

| 項目 | 前回の想定 | 実際（今回の調査） |
|------|-----------|-----------------|
| 廃止方法 | 廃止ボタンで即時delete | 自動更新OFFで期限切れ廃止（明示的deleteボタンなし）→ ハッカソンはEPP準拠でdelete直接実装 |
| 復旧のコスト表示 | なし | 追加費用（復旧手数料）が発生する旨の警告が必要 |
| 移管IN手順 | authInfo入力が最初 | **移管可否確認 → authCode入力** の順番 |
| 移管完了時間 | 20分（ハッカソン設定） | 実際は10日前後。ハッカソンは20分自動承認 |
| 更新画面 | 詳細画面から遷移 | 独立した「更新リスト」画面が存在 |
| ドメイン詳細 | 単純な情報表示 | 変更履歴・AuthCode・公開代行設定等も含む多機能なハブ画面 |
